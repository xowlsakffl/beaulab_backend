# 백엔드 보완 및 배포 점검

작성 기준: 2026-09-08. 기존 도메인 API와 상태 정의를 유지하면서 보안, 동시성, 파일 수명 및 비동기 복구를 보완한다.

## 반영 내용

| 영역 | 현재 처리 |
|---|---|
| 공지/FAQ | HTML 허용 목록 기반 정제. 저장 시 및 기존 콘텐츠 응답 시 적용한다. 에디터 임시 파일은 작성 직원별 경로를 사용하고 경로 순회와 타 직원 임시 파일 처리를 차단한다. |
| 비밀번호 재설정 | 계정 행, 토큰 행 순서로 잠근 뒤 검증/변경/토큰 삭제를 한 트랜잭션으로 처리한다. 링크 발급도 같은 계정 잠금을 사용한다. 검증 API는 만료 토큰을 삭제하지 않는다. |
| 광고 구좌 | 모든 구좌 변경 Action이 공통 잠금 행을 먼저 획득한다. 빈 구좌에도 잠금이 존재하므로 동시 승인/등록이 정원 검사를 함께 통과하지 않는다. |
| 신고 | 대상 상태를 먼저 잠그고 신고 중복 확인/저장/집계를 수행한다. MySQL REPEATABLE READ에서 먼저 열린 읽기 스냅샷으로 집계하지 않도록 한다. |
| 이벤트 DB | 이벤트 행을 먼저 잠근 뒤 신청 가능 여부와 동일 신청 여부를 다시 확인한다. 동시 동일 신청도 신규/중복 판정 순서가 정해진다. |
| 파일 | 민감 컬렉션 비공개 저장, 서명 URL 제공. 파일 삭제는 DB에 삭제 대기를 기록한 뒤 스케줄러가 수행한다. 신규 업로드 정리 기록은 DB 롤백과 독립된 비공개 파일로 보존한다. |
| SMS | PROCESSING 5분 경과 시 복구 판단. 업체가 멱등 재시도를 보장하는 경우에만 재전송하고, 결과가 불명확한 비멱등 업체 발송은 실패로 남겨 확인하게 한다. |
| Push | 발송 세대, 본문 스냅샷, 기기별 성공/실패/재시도, 워커 임대를 저장한다. Job 하나가 기기 하나를 처리하고 완료한 기기는 반복 발송하지 않는다. |
| 채팅 | 메시지/첨부/알림함을 함께 커밋한다. 브로드캐스트 실패는 저장 성공 응답과 분리하고 미완료 메시지를 다시 큐에 넣는다. |
| 운영 이력 | 병원/일반회원 상세의 현재 상태 이력은 관련 1건만 조회한다. 전체 운영 이력 API는 기존대로 유지한다. |
| 로그/설정 | 감사 로그에서 비밀번호·토큰 등을 제외한다. 내부 도구 허용 목록은 config에서 읽는다. Telescope에서 인증 경로, 원문 메일/외부 HTTP/Redis/캐시 내용 및 비밀 컬럼 SQL 수집을 제한한다. |
| Seeder/CI | 개발용 가상 데이터는 local/testing으로 제한한다. master 포함 CI에서 PHPUnit, MySQL, Redis, PHP 문법 및 Composer 보안 검사를 실행한다. |

레이어 재설계, 금액 계산 방식 변경, 권한 체계 통합, 캐시 프레임워크 교체는 하지 않는다. 충전금 원장과 환불의 기존 잠금/멱등성/불변 조건은 유지한다.

## 데이터 변경

추가 마이그레이션은 다음 4개다. 기존 마이그레이션을 다시 쓰거나 기존 업무 데이터를 초기화하지 않는다.

- `2026_09_08_000001`: `hospital_event_ad_booking_locks`, 잠금 기준 행 ID 1.
- `2026_09_08_000002`: `media_file_deletions`, 커밋된 물리 파일 삭제 대기 기록.
- `2026_09_08_000003`: `notification_deliveries`에 `generation`, `message_snapshot`, `device_results`, `lease_token`, `processing_until`, `next_attempt_at` 추가.
- `2026_09_08_000004`: `chat_messages.broadcast_pending` 추가. 기존 메시지는 false이므로 과거 메시지를 다시 발행하지 않는다.

기존 pending Push는 다음 처리 시 스냅샷을 확정한다. 기존 성공/실패 발송 상태를 일괄 변경하지 않는다.

## 파일 저장 및 호환성

- 민감 파일 목록은 `config/media.php`의 소유 모델/컬렉션 조합이 기준이다. 사업자/면허/환불 서류, 리얼모델 신청 이미지, 평가 영수증, 채팅 첨부를 포함한다.
- 기본 비공개 디스크는 `storage/app/private/media`이다. 이 디렉터리에 공개 심볼릭 링크를 만들지 않는다. 다중 서버는 동일한 비공개 공유 디스크를 설정해야 한다.
- 기존 응답 키는 유지하지만 민감 파일의 `path`, variant `path`는 5분 유효한 서명 URL이다. 공개 이미지 경로는 바뀌지 않는다.
- 프론트 공통 URL 해석기는 절대 URL을 처리한다. 단, 오래 열린 화면에서 만료된 URL을 사용할 때는 상세 데이터를 재조회해야 한다. 파일명은 `metadata.original_name`을 우선해야 한다. 장시간 화면의 자동 URL 갱신과 개별 클라이언트의 파일명 표시까지 이번 백엔드 검증에서 보장하지 않는다.
- 서명 URL을 가진 사람은 유효기간 동안 파일에 접근할 수 있다. URL 발급은 기존 소유권/권한 검사된 API 응답에서만 수행한다. 외부로 전달하거나 로그에 남기지 않는다.
- DB 롤백은 기존 파일 삭제를 취소한다. 스케줄러는 커밋된 삭제 기록만 물리 삭제하고 실패하면 다시 시도한다.
- 24시간이 지난 업로드 기록 중 DB 참조가 없는 파일만 고아 업로드로 정리한다. 실행 중인 매우 긴 트랜잭션에 대해 24시간 이상 업로드를 유지하는 운영은 지원하지 않는다.
- 기존 직원 구분 없는 에디터 임시 파일은 더 이상 게시물로 승격할 수 없다. 이전 편집 중 이미지가 있으면 다시 업로드한다.

### 기존 민감 파일 이전

신규 업로드의 비공개 저장만으로 기존 공개 파일까지 보호되지는 않는다. 아래 순서를 별도 점검 후 실행한다.

1. DB/파일 백업, 대상 컬렉션 및 스토리지 접근 권한 확인.
2. 쓰기 작업을 중지하고 신규 코드/마이그레이션 적용.
3. `php artisan media:privatize --limit=500`으로 후보 ID만 확인한다. 기본 실행은 읽기 전용이다.
4. `php artisan media:privatize --apply --limit=500`을 실행한다. 원본/variant를 복사하고 SHA-256 일치 확인 후 DB 디스크를 변경한다. 원본 삭제는 대기 기록으로 남긴다.
5. 후보가 없어질 때까지 반복한다. 원본 누락/복사 실패가 있으면 해당 파일을 복구하고 재시도한다.
6. 권한 있는 화면의 조회/다운로드 확인 후 `php artisan media:cleanup-files`로 이전 원본을 정리한다. 스케줄러도 같은 작업을 수행한다.
7. CDN·프록시·공개 버킷의 기존 캐시/복제본도 별도 제거하고 예전 공개 URL이 열리지 않는지 확인한다.

이 명령은 soft-deleted Media를 대상으로 하지 않는다. 과거 삭제 파일과 DB 참조 없는 공개 파일은 백업·보존 정책을 확인해 별도 정리해야 한다. 파일 이전 후 이전 버전 코드를 배포하면 private 디스크를 읽지 못할 수 있으므로 단순 코드 롤백만으로 복구하지 않는다.

## 큐 및 외부 연동 보장 범위

- `chat`, `notifications`, `sms`, `mail` 소비자와 매분 Scheduler가 필요하다.
- Push의 기기 결과는 현재 발송 세대에만 기록한다. 이전 워커 결과가 새 알림 세대를 덮어쓰지 않는다.
- 일시적인 FCM/APNs 429/5xx 또는 전송 예외는 해당 기기만 최대 3회 시도한다. 영구 실패와 무효 토큰은 별도 결과로 남긴다.
- 외부 업체가 수락한 직후 워커가 죽으면 DB에 성공을 기록하지 못할 수 있다. Push/Reverb는 정확히 한 번 전달을 보장하지 않는다. 클라이언트는 알림 ID/메시지 ID로 중복을 처리해야 한다.
- SMS 재시도 안전성은 `SmsProvider::supportsIdempotentRetries()` 계약에 따른다. 향후 실업체 연결 시 동일 키 재시도와 업체 결과 조회 정책을 먼저 검증해야 한다.
- 알림함 데이터는 DB에 남는다. 인앱 이벤트 큐 등록 실패 시 실시간 갱신이 늦을 수 있으며 목록 재조회로 복구한다.
- 실 SMS/FCM/APNs/Reverb 업체에 대한 발송 검증은 이번 작업에서 실행하지 않았다.

## 운영 배포

1. DB 및 스토리지 백업 후 쓰기 요청과 기존 워커를 중지한다. 구 버전/신 버전 광고 쓰기 Action이 동시에 실행되지 않게 한다.
2. `composer install --no-dev --no-interaction --prefer-dist --optimize-autoloader`.
3. `php artisan migrate --force`. 큰 테이블의 ALTER 잠금 시간은 운영 복제 환경에서 사전 측정한다.
4. 내부 도구 허용 목록, 비공개 디스크, 큐 설정 확인 후 `php artisan config:cache`.
5. 필요한 기존 파일 이전을 위 절차로 진행한다.
6. 프로세스 관리자에서 Horizon/Reverb를 새 코드로 재시작한다. `chat` 소비자 활성 여부를 확인한다.
7. `php artisan schedule-monitor:sync`, `php artisan schedule:list` 및 큐 적체 확인.
8. `php artisan hospital-wallet:audit-integrity`, 권한별 로그인/재설정/파일 조회 및 광고 등록 확인.

운영 Seeder를 실행해 기존 직원을 변경하거나 가상 충전금을 생성하지 않는다. `DatabaseSeeder`의 개발 데이터 차단은 안전장치이며 운영 데이터 갱신 명령을 대신하지 않는다.

과거 `activity_log.properties.attributes.password`/`old.password`, Telescope 및 백업에 이미 남은 비밀 값은 이번 코드 변경으로 자동 삭제되지 않는다. 보존/사고 대응 정책을 확인하고 해당 키 삭제, 노출 가능 토큰 폐기 및 필요한 비밀번호 재설정을 별도 수행한다. 전체 업무 감사 로그를 통째로 삭제하지 않는다.

## 검증

- 새 테스트 파일/테스트 케이스는 추가하지 않았다. 기존 테스트 부트스트랩, 세션 인증 및 암호화된 SMS 본문 fixture만 현재 구현에 맞췄다.
- 전체 기존 테스트: 37개, 113 assertions 통과.
- PHP 1,068개 파일 문법 검사, 변경 PHP 파일 Pint 및 `git diff --check` 통과.
- 별도 `beaulab_testing` MySQL DB에서 전체 마이그레이션 및 기능 테스트. Redis는 테스트 prefix/DB 15로 분리했다.
- 파일 경로 순회/인코딩/역슬래시 거부, HTML 공격 속성/스킴 제거, 기본 서식 보존 확인.
- 민감 파일 업로드, 서명 유효/만료, 삭제 롤백, 레거시 복사 checksum 및 원본 정리 확인.
- 실제 HTTP Kernel에서도 웹 헤더 포함 서명 파일 조회 200/no-store, 변조·만료 서명 403을 확인했다.
- 동일 재설정 토큰 동시 사용: 성공 1건/거절 1건, 감사 로그 비밀번호 미기록 확인.
- 모의 FCM 503 후 복구 시 성공 기기 재발송 없음, 비멱등 SMS의 불명확한 발송 자동 재전송 차단 확인.
- 현재 로컬 충전금 무결성 검사 10개 항목 위반 0건. 실제 충전/소진/환불 처리는 실행하지 않았다.
- Composer 보안 공지를 확인해 허용 버전 범위 내 종속성을 갱신했고 최종 audit 공지는 0건이다. 운영 트래픽, 실서비스 장애, 전체 도메인 동시 부하를 재현한 것은 아니다.
- 로컬 `beaulab`에는 추가 마이그레이션 4개만 적용했다. 기존 민감 파일 이전은 dry run만 실행했고 실파일 대량 이전/과거 로그 정리/운영 배포/워커 재시작은 실행하지 않았다.
