# 병원 챗봇 테스트 케이스

PRD의 Acceptance Criteria(12장)와 예외 시나리오(14장)를 실제로 확인하는 케이스로 옮긴 문서입니다. 각 케이스에 **자동 테스트가 덮는지**와 **사람이 봐야 하는지**를 적었습니다.

자동 테스트가 있는 항목은 회귀 때 다시 사람이 볼 필요가 없습니다. 사람 확인이 필요한 항목만 배포 전에 훑으면 됩니다.

## 표기

| 표기 | 뜻 |
|---|---|
| 자동 | 자동 테스트가 덮는다. 파일명을 함께 적었다 |
| 사람 | 브라우저에서 사람이 봐야 한다 |
| 미검증 | 아직 아무도 확인하지 않았다 |

## 배포 전 훑을 것 (QA-08)

자동 테스트가 덮지 못하는 것만 모았습니다. 확인한 것은 취소선으로 남겨 두었습니다.

1. ~~병원 계정으로 위젯을 열고 닫아도 Host 화면이 멀쩡한가 (9.2)~~ — 2026-09-28 확인
2. 두 탭에서 **동시에** 상담을 요청해도 한 건으로 수렴하는가 (2.3)
3. 좁은 화면에서 패널이 넘치지 않는가 (9.4)
4. ~~내려받은 CSV를 **엑셀로 실제로 열어** 한국어가 깨지지 않는가 (7.6)~~ — 2026-09-28 확인, 정상
5. 대기 중 새로고침이 대기 화면으로 복구되는가 (2.6)
6. 네트워크를 끊었다 붙였을 때 메시지가 중복·누락 없이 맞춰지는가 (4.8)
7. **상담원 둘이 동시에** 연결을 눌렀을 때 한 명만 성공하는가 (3.2) — 상담원 계정이 둘 필요합니다. 자동 테스트는 덮습니다
8. 지정 운영 환경에 적용했을 때 회귀가 없는가 (9.5)

## 실시간 범위에 대한 단서

현재 `BROADCAST_CONNECTION=log`로 **발행을 끄고 폴링으로 운영**합니다(메시지 5초, 목록 10초). 따라서:

- 4.8의 "네트워크 복구"는 WebSocket 재연결이 아니라 **폴링이 다시 도는지**를 봅니다
- 5.1의 전환 지연은 폴링 주기가 상한입니다. 실제로는 0.7초에 바뀌었습니다
- Reverb를 켜게 되면 9장에 WebSocket 재연결·인가 케이스를 더해야 합니다
