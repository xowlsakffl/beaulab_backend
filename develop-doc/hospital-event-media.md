# 이벤트 전후사진

텍스트 등록 이벤트에 선택적으로 최대 4세트(전/후 각 1장)를 등록한다. 실제 이미지 여부와 JPG/JPEG/PNG, 장당 5MB를 검사하며 비율/픽셀 제한은 두지 않는다.

## 실시간 미리보기

- `GET /staff/hospital-events/preview-context`: 이벤트 조회/등록/수정 권한 중 하나가 필요하다.
- `hospital_id`와 선택한 `doctor_ids`(최대 3명)를 받아 해당 병원의 활성 장점과 의료진 이름/직책/경력/활동/프로필 사진만 반환한다. 다른 병원의 의료진 ID는 거부한다.
- 텍스트 및 로컬 이미지 미리보기는 프론트 폼 상태로 처리한다. 이 API는 저장이나 파일 업로드를 하지 않는다.

## 저장

- 기존 `media` 테이블을 사용한다. `HospitalEvent` 소유의 `before_photo`, `after_photo` 컬렉션을 같은 `sort_order`로 짝짓는다. 별도 마이그레이션은 없다.
- 등록/수정/복제 요청의 `before_after_photos` 배열은 표시 순서의 전체 세트다. 각 항목은 `before_image` 또는 `before_media_id`, `after_image` 또는 `after_media_id`를 전달한다. 같은 쪽에 파일과 ID를 동시에 전달할 수 없다.
- 수정 시 필드 생략은 기존 사진 유지, 빈 배열은 전체 삭제다. multipart에서 빈 배열은 `before_after_photos`에 JSON 문자열 `[]`를 보낸다.
- 기존 미디어 ID는 수정 대상 이벤트(복제는 원본 이벤트)의 해당 전/후 컬렉션 소유권을 검사한다. 다른 이벤트의 파일, 중복 ID, 불완전한 세트는 거부한다.
- 이미지 등록으로 저장하면 전후사진을 제거한다. 이미지 유형에 전후사진을 포함한 요청은 거부한다.
- 상세 응답의 `before_after_photos`는 `before_image`, `after_image` 미디어 DTO 배열이다. 생성/수정/복제 응답도 같은 형식이다.
- 복제는 원본 파일을 새 이벤트 경로로 복사한다. 원본과 파일을 공유하지 않는다.
- 사진 교체/삭제는 기존 미디어 파일 수명 관리와 이벤트 트랜잭션에 포함한다. 수정 내역은 운영 히스토리에 세트별 전/후 원본 파일명으로 기록하며, 사진이 없으면 `-`로 표시한다. 기존에 기록한 히스토리는 변경하지 않는다.
- 의료진 전체 해제는 `doctor_assignments`에 JSON 문자열 `[]`를 전달한다. 병의원 변경 시 의료진 필드가 생략되면 기존 의료진의 소속을 다시 검증한다. 부작용 안내는 명시적인 `null`(빈 문자열 정규화)로 삭제하고, 필드 생략은 기존 값을 유지한다.
