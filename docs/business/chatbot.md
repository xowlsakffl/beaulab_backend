# 병의원 챗봇과 상담

## 역할

Q&A로 자주 묻는 내용을 탐색하고, 필요하면 병의원이 직원 상담을 요청합니다. 회원 간 채팅과는 모델·권한·UI가 다릅니다.

직원 메뉴는 챗봇 통계, 병의원 상담, Q&A 관리, 상담 운영 관리입니다. 통계 조회는 상담 조회와 별도 권한입니다. Q&A·운영 설정도 각각 조회·관리 권한을 검사합니다.

## Q&A

현재 사용자 탐색 기준은 Q&A 자체의 `parent_id` 트리입니다. 최대 3단계이며 선택 문구는 필수, 답변은 선택입니다. 공개되지 않은 상위의 하위는 병의원 조회 결과에서도 제외됩니다.

같은 부모 아래의 질문 중복과 자기 자신·자손으로의 이동을 막습니다. 상위 삭제는 하위 이동·삭제 후 가능합니다. 드래그는 형제 순서와 부모 변경을 구분하고 서버에서 최종 검증합니다.

과거 폴더 모델·컬럼은 호환용으로 남아 있습니다. 새 화면이 폴더 기반이라는 설명은 맞지 않습니다. Q&A 탐색 대화는 위젯 메모리에 유지되고, 상담 요청 시 마지막 선택 질문·답변의 사본을 저장합니다. 이후 질문을 수정해도 과거 상담 문맥을 덮어쓰지 않습니다.

## 상담 상태

| 전환                | 주체 / 조건                       |
| ------------------- | --------------------------------- |
| 새 요청 → WAITING   | 운영 가능 여부와 소속 병의원 확인 |
| WAITING → CONNECTED | 처리 권한 직원이 담당 수락        |
| WAITING → CANCELED  | 병의원 취소 또는 대기 만료        |
| CONNECTED → ENDED   | 담당 직원 또는 해당 병의원        |

병의원당 활성 상담은 하나이며 활성 병의원 키와 조건부 갱신으로 동시 요청·동시 수락을 제어합니다. 수락 시 자동 연결 인사를 서버가 한 번만 생성합니다. `{상담원명}`은 서버에서 치환합니다.

병의원은 본인 병의원의 종료된 상담과 메시지도 조회할 수 있습니다. 현재 정책은 '종료 기록은 직원만 조회'가 아닙니다. 직원도 조회·처리 범위를 구분하며 다른 직원의 담당 상담을 무조건 종료할 수 없습니다.

## 메시지와 실시간

메시지에는 상담 내 순번과 `client_message_id`가 있습니다. 재전송은 원래 ID를 유지해 중복 생성을 막습니다. 커서 조회는 최신·이후·이전 메시지를 구분합니다.

실시간 이벤트는 변경을 알리고 API를 재조회하는 방식입니다. 상담 상태 버전과 메시지 순번을 확인하므로 도착 순서나 재연결만으로 메시지가 누락되지 않아야 합니다. 웹소켓이 끊기면 보조 조회로 복구합니다. Reverb 연결만 성공하고 전용 큐가 멈춰 있으면 실시간 반영은 되지 않을 수 있습니다.

상태·메시지 저장 후 방송이 실패해도 데이터 저장을 취소하지 않습니다. 발행 대기·재시도 경로가 처리합니다. 프론트 SDK의 자세한 계약은 [SDK 문서](https://github.com/beaulab/beaulab_new_frontend/blob/master/docs/chatbot-sdk.md)를 따릅니다.

## 운영 설정

운영시간, 점심시간, 휴무일, 강제 중단과 안내 문구·상담 매크로를 관리합니다. 기준 시간대는 Asia/Seoul입니다. 병의원 availability 응답이 현재 운영 여부를 판단하며 위젯이 독자적으로 영업일을 계산하지 않습니다.

대기 만료 기본값은 30분이며 스케줄러가 처리합니다. 강제 중단은 특정 휴일 날짜와 다른 상태입니다. 매크로는 입력 보조이고 선택 자체가 메시지 전송을 뜻하지 않습니다.

## 통계와 보관

위젯 열림·질문 조회 이벤트, 상담 요청·연결·종료 기록을 별도로 수집합니다. 이벤트 보관 기본값은 180일입니다. 이는 상담 메시지의 보관 기간을 뜻하지 않습니다.

CSV 내보내기는 현재 동기 처리이며 최대 기간 92일, 행 10,000개, 청크 500개 제한이 있습니다. 민감한 대화 내보내기 권한과 파일 전달 경로를 확인해야 합니다.
