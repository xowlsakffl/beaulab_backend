# 상담신청과 고객 DB

## 구분

| 구분        | 연결 대상                      | 주요 동작                        |
| ----------- | ------------------------------ | -------------------------------- |
| 이벤트 DB   | 회원·이벤트·병의원·선택 의료진 | 신청 접수와 중복 구분, 상태 관리 |
| 비대면 상담 | 회원 신청·여러 병의원의 견적   | 검수, 배정·취소, 병의원 답변     |
| 리얼모델    | 기획전 이벤트·신청 회원·이미지 | 신청·검수·상태 관리              |

화면에서는 모두 고객 DB 아래에 있지만 동일한 처리·과금 규칙으로 합치지 않습니다.

## 이벤트 신청

사용자 신청은 이벤트가 신청 가능한 상태인지 확인하고 이벤트를 잠급니다. 선택 의료진은 해당 병의원·이벤트 조건을 만족해야 합니다. 이름·전화번호 등의 기존 신청 여부를 기준으로 신규·중복 신청을 구분합니다.

신청에는 동의값과 신청 당시 이벤트 가격·상담신청 단가를 저장합니다. 이후 단가표를 수정해도 과거 신청의 스냅샷을 다시 계산하지 않습니다.

현재 사용자 생성 Action은 신청과 직원 알림을 생성하지만 포인트 차감 Action을 호출하지 않습니다. '병의원이 답변할 때 차감'이라는 목표를 이벤트 DB까지 완성된 기능으로 설명하지 않습니다.

## 비대면 배정

신청 시 자동 배정 내부 Action과 직원 직접 배정 기능이 있습니다. 자동 배정은 우선 선택과 무작위 후보를 합쳐 최대 6개 병의원을 구성합니다. 코드의 `random-v1`이며 AI 추천이 아닙니다.

후보 병의원은 정상 운영·검수 승인, 정상 병의원 계정, 관련 진료과목, 현재 상담비용 이상의 사용 가능 잔액 조건을 만족해야 합니다. 잔액 부족 병의원은 자동 무작위 배정 대상이 아닙니다.

직원 직접 배정은 `PENDING / REVIEWING` 단계에서 가능합니다. 직접 배정 권한 하나가 배정과 취소를 담당합니다. 이미 답변한 견적은 취소할 수 없습니다. 후보 화면에서 잔액 부족 항목을 보여 주더라도 선택 가능 여부를 구분합니다.

배정 자체는 잔액을 예약하지 않습니다. 배정 후 다른 업무로 잔액이 줄 수 있으므로 답변 시 다시 검사합니다.

## 검수와 답변

1. 검수 승인에는 유효 카테고리·회원 이미지 등 신청 조건과 배정 후보의 유효성을 확인합니다.
2. 병의원은 자기 병의원에 배정된 견적에만 답변할 수 있습니다.
3. 신청이 승인 상태이고 병의원·계정이 유효해야 합니다.
4. 최초 답변은 답변 시점의 비대면 고정 단가를 조회합니다.
5. 지갑을 잠그고 서비스 포인트부터, 부족한 나머지는 유상 포인트에서 차감합니다.
6. 잔액 부족이면 답변과 거래 모두 확정하지 않습니다. 차감과 답변은 같은 업무 트랜잭션 안에서 처리합니다.
7. 동일 견적의 재요청·수정은 추가 차감하지 않습니다. 거래 멱등 키는 견적 ID에 연결됩니다. 단가가 0이면 차감 원장을 만들지 않는 경로가 있습니다.

견적 조회는 비대면 조회 권한을 따릅니다. 서버 내부 상수에 APPROVE가 남아 있어도 화면의 업무 의미는 상태 처리입니다.

## 리얼모델

신청 회원·이벤트·이미지와 상태를 관리하며 직원 알림을 발행합니다. 카테고리·가격 구간별이 아닌 고정 단가 설정이 존재합니다. 그러나 현재 리얼모델 생성 Action과 답변 과금의 연결은 확인되지 않습니다.

## 구현 경계

- 비대면 사용자 제출용 API 라우트는 현재 확인되지 않습니다. 내부 자동 배정 Action이 있다는 이유로 회원 앱 신청 흐름까지 연결됐다고 보지 않습니다.
- 현재 지갑 사용 완료 Action의 상담 답변 호출자는 비대면 답변입니다. 이벤트·리얼모델 과금 적용을 확대하려면 차감 시점·환원·중복 답변 정책부터 확정해야 합니다.
- 검수 승인 자체를 과금 성공으로 해석하지 않습니다.
