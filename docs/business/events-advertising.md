# 이벤트·광고·노출

## 각각의 역할

- 이벤트: 병의원의 상품·시술 소개와 상담신청 대상.
- 이벤트 광고: 이벤트를 특정 위치·기간에 광고하는 예약·검수 데이터.
- 노출 설정: 배너·팝업·후기·영상·이벤트의 사용자 화면 배치와 순서.
- 병의원 프로모션: 병의원 단위 홍보 영역과 게시기간.

같은 화면에 표시된다고 하나의 상태·가격·권한으로 합치지 않습니다.

## 이벤트 등록과 공개

이벤트는 병의원, 담당 직원, 대표 카테고리, 선택 의료진, 썸네일과 본문 미디어에 연결됩니다. 이미지형과 텍스트형은 입력 구조가 다릅니다. 텍스트형 시술대상·장점·옵션과 전후 사진 조건은 이벤트 Request·Model에서 관리합니다.

현재 상수는 카테고리 최대 3개, 의료진 최대 3명, 전후 사진 최대 4개, 할인율 최대 49%입니다. 세부 입력 규칙은 서버 검증과 일치시킵니다.

| 상태 축     | 값 / 의미                              |
| ----------- | -------------------------------------- |
| 검수        | PENDING, REVIEWING, APPROVED, REJECTED |
| 병의원 공개 | PUBLIC, PRIVATE                        |
| 관리자 운영 | NORMAL, FORCED_STOPPED                 |
| 기간        | 시작·종료·무기한 여부                  |

신청 가능한 이벤트는 공개·관리자 정상·검수 승인·신청 기간 조건을 만족해야 합니다. 사용자 조회에서는 소속 병의원의 공개 가능 상태도 확인합니다. 검수 승인 하나만으로 노출된다고 설명하지 않습니다.

상담신청 단가는 직접 입력하는 독립 필드가 아니라 대표 카테고리와 현재 단가 정책에서 결정합니다. 신청 시점 스냅샷은 [상담신청](consultations.md)을 따릅니다.

## 광고 예약

광고는 병의원·이벤트·위치·카테고리·기간·비용·광고 이미지에 연결됩니다. 메인, 성형, 쁘띠, 기타 위치를 구분하고 위치에 따라 카테고리가 필요합니다.

검수 상태와 광고예정·광고중·광고종료는 다릅니다. 예정·진행·종료는 승인 여부 및 현재 시각과 기간으로 산출됩니다. 시작 요일과 슬롯 제한은 위치별 규칙이며 공통 달력 UI가 임의로 정하지 않습니다.

예약 충돌은 동일 위치·대상·기간에 대한 서버 잠금과 검사로 처리합니다. 예약에 쓰인 카테고리·이벤트를 변경할 때 이미 유효한 예약을 깨뜨리지 않아야 합니다. 비용 기본값 변경을 기존 예약 가격에 소급 적용하지 않습니다.

광고 관리 조회와 광고 현황 조회는 별도 permission입니다. 가격표 관리는 또 다른 기능입니다.

## 노출 설정

노출 대상 선택, 기간, 순서, 공개 여부를 관리합니다. 배너·팝업과 기타 노출설정은 권한을 구분합니다. 순서 이동은 화면 배열만 바꾸는 기능이 아니며 서버의 위치·순서 버전을 확인합니다.

현재 정렬 손잡이, 검색 모달, 콘텐츠 선택 화면은 기존 공통 UI를 사용합니다. 공개 조회·클릭 API가 있다고 소비자 앱의 모든 배치가 실제 출시되었다는 뜻은 아닙니다.

프로모션의 기간·슬롯 중복 검사는 이벤트 광고와 별도 정책입니다. 잠금 구현을 공유할 수 있어도 서로 다른 상품의 정원과 기간을 하나로 합치지 않습니다.
