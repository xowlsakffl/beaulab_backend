# 병의원과 계정

## 목적과 데이터 관계

직원이 입점신청을 검토하고 병의원·의료진 정보를 관리합니다. 병의원 로그인 계정은 별도 생성·인증 흐름을 가집니다.

| 데이터               | 역할                                     |
| -------------------- | ---------------------------------------- |
| HospitalEntry        | 입점 신청 및 검수 자료                   |
| Hospital             | 병의원 기본·운영·사업자·계좌·미디어 정보 |
| HospitalDoctor       | 특정 병의원 소속 의료진                  |
| AccountHospital      | 병의원에 연결된 로그인 계정              |
| 상태 변경 요청       | 직접 변경과 구분되는 운영중지·재개 요청  |
| 관리자 메모·히스토리 | 대상별 내부 기록                         |

병의원 레코드가 있어도 계정은 없을 수 있습니다. 병의원 운영 중지, 계정 정지, 계정 미생성, 마지막 접속 시각은 서로 다른 값입니다.

## 등록·검수·수정

병의원과 의료진은 상세 정보·이미지·분류를 저장하고 검수 상태를 관리합니다. 수정 시 기존 파일 유지·교체·삭제를 구분하며, 이미지 순서는 파일 ID와 신규 업로드 인덱스로 전달합니다. 대표 이미지 변경을 이미지 삭제·재등록으로 처리하지 않습니다.

검수 상태는 `NOT_APPLIED / PENDING / REVIEWING / APPROVED / REJECTED`이고 병의원 운영 상태는 `ACTIVE / SUSPENDED / WITHDRAWN`입니다. 같은 상태값으로 합치지 않습니다. 필수값·허용 전환·반려 사유는 해당 Request·Action·Policy가 검증합니다.

분과는 관리 가능한 분류이지만 저장된 분과 코드를 보존하는 구조입니다. 진료과목·의료진 진료분야와는 다른 카테고리 사용처입니다. 자세한 규칙은 [카테고리](categories.md)를 따릅니다.

## 운영중지·재개

- 상태 변경 권한이 있으면 직접 처리할 수 있습니다.
- 요청 권한만 있는 직원은 목표 상태와 사유를 담은 요청을 생성합니다.
- 같은 병의원의 미처리 요청이 있거나 현재 상태와 목표 상태가 같으면 중복 요청을 막습니다.
- 요청 처리 권한을 가진 직원에게 알림을 보냅니다.
- 승인자는 본인이 만든 요청을 승인할 수 없습니다.
- 승인 시 병의원 현재 상태가 요청 당시 상태와 같은지 검사합니다. 이미 달라졌다면 과거 요청으로 덮어쓰지 않습니다.
- 반려에는 사유가 필요합니다. 처리 결과는 요청자에게 알립니다.
- 직접 변경으로 기존 미처리 요청의 전제가 깨지면 해당 요청을 취소 처리합니다.

요청·직접 변경·승인·반려는 히스토리와 요청자·처리자 정보를 유지합니다. 역할명이 아닌 서버 권한으로 판단합니다.

## 병의원 계정

계정 초대 발송, 이메일 인증·계정 생성, 비밀번호 재설정은 별도 보안 흐름입니다. 재발송 시 이전 초대의 유효성을 갱신·무효화하는 정책을 따릅니다. 초대 토큰을 로그나 문서에 넣지 않습니다.

초대 링크 확인 → 이메일 인증번호 발송 → 코드 검증 → 인증 증표로 계정 생성 순서입니다. 초대·이메일 인증 증표를 잠그고 소비해 같은 증표로 계정을 중복 생성하지 않습니다. 원본 토큰 대신 해시를 저장하며 이메일과 초대의 연결도 확인합니다.

기본값은 초대 72시간, 이메일 코드 5분, 인증 증표 15분, 재발송 간격 60초, 코드 시도 최대 5회입니다. 실제 값은 [초대 설정](../../config/hospital_account_invitation.php)이 우선합니다. 병의원 비밀번호 재설정 링크는 기본 60분이며 이전 링크 폐기·사용 완료·현재 자격 증명과의 일치를 확인합니다. 메일 대기 등록과 수신 성공은 다르므로 발송 실패를 별도로 확인합니다.

직원 UI는 발송 중심입니다. 서버에 초대 취소 DELETE 경로가 남아 있으므로 '폐기 기능이 전혀 없다'고 단정하지 않습니다. API 소비 여부와 폐기 정책을 바꾸려면 별도 검토가 필요합니다.

병의원 삭제 API는 현재 직원 라우트에 없습니다. 권한표에 이름이 비슷한 항목이 남아 있더라도 실제 삭제 기능으로 안내하지 않습니다.

## 파일과 권한

사업자등록증·계좌 증빙 등은 일반 공개 홍보 이미지와 접근 조건이 다릅니다. 원본 보기·다운로드는 미디어 접근 정책과 서명 URL을 사용합니다. 파일명은 URL의 `original?expires=...`가 아니라 저장 메타데이터를 표시합니다.

조회·등록·수정·검수/운영 상태·요청 처리·초대·비밀번호 재설정 권한은 각 서버 정책을 따릅니다. 메모 작성 권한이 있다는 이유로 병의원 전체 수정 권한이 생기지 않습니다.
