# 회원과 콘텐츠

## 회원

일반회원은 직원·병의원 계정과 별도 모델입니다. 상태는 정상·정지·차단·탈퇴이며 가입 경로, 마지막 접속, 동의 설정, 경고 수 등을 관리합니다.

직원은 조회·수정·상태 변경 등 자신의 권한 범위에서 처리합니다. 회원 본인 API는 인증 주체와 리소스 소유권을 검사합니다. URL의 회원 ID만으로 다른 사람의 콘텐츠·채팅을 조회할 수 있는 구조로 만들지 않습니다.

관리 화면의 상담신청정보·활동정보·신고게시물은 서로 다른 관계의 집계입니다. 비어 있는 값과 조회 실패를 구분합니다. 접속 기록은 방문자 통계의 방문 세션과 동일한 지표가 아닙니다.

## 콘텐츠별 관계

| 도메인      | 주요 데이터                                                | 별도 규칙                           |
| ----------- | ---------------------------------------------------------- | ----------------------------------- |
| 후기        | 작성 회원, 병의원·의료진, 카테고리, 비용·평점, 전후 이미지 | 성형·시술 구분, 댓글·좋아요·저장    |
| 토크        | 작성 회원, 유형, 제목·본문·이미지, 투표                    | 성형·쁘띠·일상·비밀, 고정 순서      |
| 병의원 평가 | 작성 회원·병의원·의료진, 항목별 평점, 이미지·영수증        | 게시물 상태와 영수증 인증 상태      |
| 동영상      | 병의원·의료진, 영상·썸네일·분류                            | 등록 검수·공개·강제중지와 동의 여부 |
| 댓글        | 원본 후기 또는 토크, 작성자, 본문                          | 원본 접근·댓글 신고·계수            |
| 회원 채팅   | 채팅방·참여자·메시지·첨부·읽음                             | 참여자 접근과 차단, 메시지 멱등성   |

후기와 토크의 댓글 UI를 공유할 수 있지만 원본 모델·권한·집계는 해당 도메인에 둡니다. 회원 채팅은 병의원과 직원의 챗봇 상담과 다른 시스템입니다.

## 작성과 공개

제목·본문·댓글·닉네임 금지어 검사는 실제 연결된 사용자 작성 Action에서 수행합니다. UI 검사만으로 보호하지 않습니다. 적용 범위와 미연결 영역은 [운영 설정](operating-settings.md)에 명시합니다.

일반 공개 상태와 신고 처리 상태를 함께 확인합니다. 자동차단·운영자 노출중지 대상은 일반 공개 토글로 우회 복구하지 못합니다. 비밀 토크는 일반 앱 탐색 결과에 섞지 않습니다.

후기의 성형·시술 타입, 토크 유형, 평가의 시술·상담 분류는 서로 다른 업무 기준입니다. 동일한 이름이 있어도 [업무별 카테고리](categories.md)를 독립 관리합니다.

## 평가와 영수증

평가의 `status`, `post_status`, `receipt_status`는 별개입니다. 영수증 첨부가 바로 인증 완료를 뜻하지 않습니다. 인증·반려 사유와 공개 가능한 게시물 상태를 각각 관리합니다.

평가 저장·삭제·복원 시 병의원의 평가 수·평점 집계가 갱신됩니다. 직접 SQL이나 이벤트를 끈 저장은 해당 파생 집계를 누락할 수 있습니다. 주기적 평점 재계산 명령도 있지만 일반 저장 흐름을 대신하는 근거는 아닙니다.

## 회원 채팅

회원 간 1:1 채팅은 첫 메시지에서 방을 만들고 두 회원의 정렬된 ID 기반 match_key로 중복 방을 방지합니다. 참여자·활성 상태와 양방향 차단을 검사합니다. 병의원 챗봇 상담방과 공유하지 않습니다.

메시지 재전송은 원래 client_message_id를 유지합니다. 답장 대상은 같은 방이어야 합니다. 목록은 before_id/after_id 커서 방식이고 읽음 커서는 뒤로 이동하지 않습니다. 내 대화 삭제는 사용자별 deleted_until_message_id까지 숨기는 동작이며 상대방 기록의 물리 삭제가 아닙니다.

메시지·첨부·필수 수신함을 저장한 뒤 외부 방송을 처리합니다. broadcast_pending과 전용 큐·주기 재발행이 있으며 수신 측은 메시지 ID로 중복을 제거합니다. 방송 실패만으로 저장된 메시지를 다시 생성하지 않습니다.

## 신고와 제재

신고 목록·상세와 경고는 [신고와 제재](moderation.md)의 기준을 따릅니다. 동영상 신고 처리는 영상 등록 관리에서 접근하는 UI 경로가 있으며 별도 신고 동영상 메뉴를 전제로 하지 않습니다.

회원 경고에 따른 자동 차단과 직원의 수동 차단은 구분합니다. 자동 경고를 취소했다고 수동 차단 계정을 정상으로 풀지 않습니다.
