# 신고와 제재

## 목적

회원 신고를 접수하고 대상의 공개 상태·경고·회원 제한을 처리합니다. 신고 접수, 콘텐츠 숨김, 회원 경고는 서로 다른 결과입니다.

대상은 후기·토크·평가·댓글·영상·회원 채팅 메시지입니다. 대상 별칭은 서버 Registry에서 허용한 모델로만 해석합니다. 클라이언트가 임의의 모델명을 보내 접근하지 못하게 합니다.

## 상태와 처리

| 코드           | 의미                                  |
| -------------- | ------------------------------------- |
| NONE           | 신고 없음                             |
| REPORTED       | 신고 접수                             |
| AUTO_BLOCKED   | 기준 충족에 따른 자동차단             |
| ADMIN_HIDDEN   | 운영자 조치                           |
| NORMAL_VISIBLE | 정상 처리                             |
| REEXPOSED      | 정상 처리 누적 후 자동 조치 제한 상태 |

일반 게시물은 노출중지·정상노출 의미로 표시하지만 채팅은 신고·무시, 영상은 삭제처리·신고오류 등 대상별 표현을 사용합니다. 동일 코드를 일괄 번역하면 히스토리 의미가 틀어집니다.

신고 접수 시 최근 1시간 10건 기준 등의 자동 조치 규칙을 적용합니다. 정상 처리 누적 3회 기준과 영상의 72시간 제한 등은 대상별 예외가 있으므로 모든 대상에 동일한 자동 숨김 함수를 강제하지 않습니다. 정확한 조건은 `ContentReportState`와 신고 생성 Action을 따릅니다.

## 직원 처리 흐름

1. 대상 유형에 맞는 조회·상태 처리 권한을 검증합니다.
2. 원본 대상과 신고 상태를 잠그고 실제 신고 접수 내역이 있는지 확인합니다.
3. 조치와 원본 공개·강제중지 상태를 같은 트랜잭션에서 변경합니다.
4. 허용되는 상태에서만 경고·무시를 처리합니다. 영상에는 같은 회원 경고 처리를 적용하지 않습니다.
5. 처리자·사유·상태 전후를 히스토리에 기록하고 알림·집계를 갱신합니다.

일반 게시물 공개 변경 화면은 `AUTO_BLOCKED / ADMIN_HIDDEN`을 해제할 수 없습니다. 오류는 해당 변경 모달의 공통 오류 영역에 표시해야 하며 목록 전체의 무관한 오류로 바꾸지 않습니다.

## 회원 경고

경고 횟수 10회 기준에 도달한 정상 계정은 자동 차단 대상입니다. `blocked_by_warning`으로 이 차단이 경고에서 비롯되었는지 구별합니다.

경고를 무시로 변경할 때 경고 수를 줄이지만, 차단 해제는 자동 차단 표시가 있고 기준 아래로 내려간 계정에만 적용합니다. 직원이 수동으로 차단한 계정과 기존 출처가 불분명한 차단을 임의 해제하지 않습니다.

동시 신고 처리로 경고 수가 중복 증가하거나 음수가 되지 않도록 작성 회원과 상태 잠금을 사용합니다. 재시도에서 기존 처리 상태도 확인합니다.

## 데이터와 화면

원본 콘텐츠, 신고 개별 기록, 집계된 대상 신고 상태, 회원 경고, 운영 히스토리를 분리합니다. 집계 상태만 보고 원래 신고 사유와 신고자를 없애지 않습니다.

신고 채팅 본문은 표가 아닌 대화 내용으로 표시할 수 있지만 신고 처리·권한·히스토리 계약은 유지합니다. 히스토리에는 생성·수정·상태 변경을 유형으로, 변경값과 사유를 내용으로 표시합니다.
