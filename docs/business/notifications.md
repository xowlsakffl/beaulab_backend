# 직원 알림

## 목적

업무를 처리할 직원에게 인앱 알림을 보내고, 헤더 수신함·메뉴 숫자·게시판 행 강조를 직원별 읽음 상태로 맞춥니다. 기존 업무 상태와 알림 상태는 독립적입니다.

신청 상태인 행이라고 항상 강조하지 않습니다. 내가 알림을 읽었다고 다른 직원의 읽음이 바뀌거나 업무가 승인되는 것도 아닙니다.

## 발행과 수신

1. 업무 트랜잭션 안에서 이벤트와 대상 직원 목록을 발행 대기함에 저장합니다.
2. 커밋 뒤 `staff-notifications` 큐가 수신함에 전달합니다. 실패한 발행 대기는 스케줄러가 다시 요청합니다.
3. 대상은 삭제되지 않은 정상 직원이며, 유형별 필수 권한과 본인 수신 설정을 검사합니다.
4. 전달 시점에도 상태·권한·설정·담당 여부를 다시 검사합니다.
5. 이벤트 키와 직원별 수신 영수증으로 재시도 중복을 막습니다.

수신 대상은 이벤트 발생 시점에 정합니다. 이후 권한을 받은 직원에게 과거 알림을 소급 배포하지 않습니다. 이벤트 발행자가 주어진 경우 자기 자신은 수신 대상에서 제외합니다.

## 유형별 기준

| 유형                                     | 기본 수신 대상 / 조건                         |
| ---------------------------------------- | --------------------------------------------- |
| 병의원·의료진·입점·이벤트·광고 검수 신청 | 해당 조회와 상태 처리 권한을 모두 가진 직원   |
| 운영 상태 변경 요청                      | 병의원 조회, 요청 조회, 요청 처리 권한 보유자 |
| 운영 상태 변경 결과                      | 원래 요청자. 현재 대상 조회 권한도 검사       |
| 상담 연결 요청                           | 병의원 상담 조회·처리 권한 보유자             |
| 상담 새 메시지                           | 현재 담당 직원. 상담 조회·처리 권한 필요      |
| 비대면 검수 신청                         | 비대면 조회·상태 처리 권한 보유자             |
| 리얼모델 신청                            | 리얼모델 조회·상태 처리 권한 보유자           |
| 이벤트 DB 생성                           | 이벤트 DB 조회 권한 보유자. 기본 수신은 꺼짐  |
| 신고 접수                                | 콘텐츠별 신고 조회·처리 규칙에 맞는 직원      |

유형이 코드에 정의되어 있다고 발행이 연결된 것은 아닙니다. 이벤트 DB 신고와 비대면 배정 확인 필요 유형은 현재 숨김 설정이며 실제 발행 연결이 없는 항목입니다. 알림 설정에서 활성 서비스 기능처럼 안내하지 않습니다.

## 읽음과 집계

- 목록을 조회하거나 미리 데이터를 가져오는 것만으로 읽음 처리하지 않습니다.
- 현재 화면의 대상 상세 조회가 성공하면 연결된 알림을 확인합니다. 이벤트 DB 등 목록 안에서 처리하는 대상은 해당 화면의 명시적 읽음 흐름을 따릅니다.
- 채팅 새 메시지는 일반 상세 진입 처리와 분리합니다. 실제 확인한 메시지 순번을 기준으로 처리합니다.
- 읽음 요청에 확인 당시 이벤트 수·메시지 기준을 전달해, 요청 도중 도착한 새 알림까지 지워지지 않도록 합니다.
- 모두 읽음은 서버가 발급한 수신함 범위 토큰을 사용합니다. 이후 도착한 항목은 미확인으로 남습니다.
- 동일 대상의 신고·채팅 알림은 묶일 수 있습니다. 메뉴 숫자는 수신함의 미확인 묶음 수이며 내부 `event_count` 합계나 신청 건수와 다를 수 있습니다.
- 업무 종료로 더 이상 조치할 필요가 없는 `resolved_at`과 직원의 `read_at`은 다릅니다. 오래된 알림이 재신청 때 다시 살아나지 않게 무효화합니다.

권한 회수 후에는 수신함 조회·집계에서도 현재 권한에 맞지 않는 항목을 제외합니다. 실시간 갱신, 탭 간 알림, 화면 복귀·보조 조회는 같은 서버 상태를 다시 조회하는 수단입니다.

## 데이터와 부작용

발행 대기·수신 영수증·직원 인앱 알림을 분리합니다. 알림 전달 실패가 원래 업무 저장을 롤백시키지는 않지만 발행 대기가 누적될 수 있으므로 큐와 재발행 일정이 필요합니다.

직원 인앱 큐는 SMS·메일·모바일 푸시 큐가 아닙니다. 사용자 알림·푸시는 별도 전달 경로이며 인앱 작업자만 실행했다고 함께 발송되는 것으로 가정하지 않습니다.
