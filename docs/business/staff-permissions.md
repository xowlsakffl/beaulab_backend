# 직원과 권한

## 목적과 주체

직원의 로그인 가능 여부, 담당 역할, 실제 업무 권한을 관리합니다. 일반 직원 관리와 본인의 내 정보 수정은 다른 기능입니다.

## 역할과 개인 권한

| 코드                  | 화면 구분 | 의미            |
| --------------------- | --------- | --------------- |
| `beaulab.super_admin` | 총괄      | 기본권한 템플릿 |
| `beaulab.admin`       | 매니저    | 기본권한 템플릿 |
| `beaulab.staff`       | 사원      | 기본권한 템플릿 |
| `beaulab.dev`         | 개발자    | 기본권한 템플릿 |

역할명만으로 모든 기능을 허용하지 않습니다. 권한 초기화가 끝난 직원은 **직접 부여된 permission**으로 인가합니다. 역할에 연결된 permission을 매번 합산하지 않습니다. 따라서 매니저라도 병의원 수정 권한을 해제하면 수정할 수 없습니다.

레거시 계정의 `permissions_initialized_at`이 비어 있으면 이전 유효 권한을 개인 권한으로 전환하는 호환 경로가 남아 있습니다. 이 상태와 초기화된 상태를 같은 것으로 취급하지 않습니다.

## 주요 흐름

1. 등록 시 기본 정보와 역할을 선택합니다. 역할 기본권한을 개인 권한으로 복사하고 정상 상태로 생성합니다.
2. 수정 시 역할을 유지하면 개인 권한표를 조정할 수 있습니다.
3. 역할을 변경하면 **새 역할의 기본권한으로 초기화**합니다. 그 요청에 전달된 기존 개인 권한을 합치지 않습니다.
4. 역할별 기본권한 수정은 이후 등록·역할 변경에 적용됩니다. 기존 직원 모두의 권한을 소급 갱신하지 않습니다.
5. 상태 변경은 확인 후 별도 요청으로 처리합니다. 기본정보 저장과 같은 동작으로 취급하지 않습니다.

직원 로그인 ID는 생성 후 바꾸지 않습니다. 이름·전화번호·부서·직급 등과 구분합니다. 내 프로필 수정과 본인 비밀번호 변경은 기본 인증 기능이며 별도의 내 정보 permission을 요구하는 관리 기능이 아닙니다.

## 인가와 보호 조건

- 등록·조회·수정·삭제·상태 변경·권한 관리를 구분합니다.
- 역할 변경이나 개인 권한 변경에는 권한 관리 권한이 필요합니다.
- 자신이 보유하지 않은 권한을 다른 직원에게 부여할 수 없습니다.
- 자기 자신을 비활성화하거나 삭제할 수 없습니다.
- 마지막 활성 직원 관리 가능 계정의 필수 권한을 제거하거나 해당 계정을 비활성화·삭제하지 못합니다.
- 직원 상태는 `ACTIVE / SUSPENDED / BLOCKED`입니다. 역할과 별개로 로그인·업무 접근을 제한합니다.
- `lock_version`·갱신 시각·역할 템플릿 버전으로 오래된 화면의 덮어쓰기를 막습니다. 충돌 시 최신값을 확인하고 다시 편집합니다.

## 메뉴와 기능 권한

충전금 현황·내역·관리, 광고 관리·현황, 영상 관리·동의 여부, 회원 관리·현황, 챗봇 통계·상담·Q&A·운영 관리는 각각 분리되어 있습니다. 권한표의 실제 항목은 `StaffPermissionCatalog`, 인가 식별자는 `AccessPermissions`를 기준으로 합니다.

비대면 직접 배정은 배정·취소를 함께 허용하고, 견적 조회는 상담 조회를 따릅니다. 메모·히스토리의 대상 접근과 쓰기 권한은 각 기능 정책을 따릅니다. 화면이 비슷하다는 이유로 모두 같은 permission으로 합치지 않습니다.

메뉴 숨김과 경로 보호는 프론트, 최종 인가는 서버 Policy·Gate의 책임입니다. 경로에 조회 권한이 없으면 공통 접근 불가 경로로 이동하고, 개별 변경 액션의 권한 오류는 해당 동작 영역에서 안내합니다.
