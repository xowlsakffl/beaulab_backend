# 충전금과 비용 설정

## 지갑과 거래

병의원 지갑은 유상 잔액, 유상 예약 잔액, 서비스 잔액을 구분합니다.

- 사용 가능한 유상 = 유상 잔액 - 유상 예약 잔액
- 총 사용 가능 = 사용 가능한 유상 + 서비스 잔액
- 포인트 P와 결제·환불의 현금 원화, 공급가액·부가세는 서로 다른 값입니다.

`HospitalWalletOperation`은 신청·처리 업무, 완료 거래와 거래 항목은 잔액 변동 원장입니다. 완료 작업에 거래를 중복 생성하지 않으며 유상·서비스 및 CREDIT·DEBIT을 나누어 기록합니다. 단순히 잔액 숫자만 바꾸면 원장과 맞지 않습니다.

## 충전·소진·환불·적립·회수

| 표시 | 의미                         |
| ---- | ---------------------------- |
| 충전 | 유상 포인트 유입             |
| 소진 | 서비스 또는 유상 포인트 사용 |
| 환불 | 유상 포인트 환불 처리        |
| 적립 | 서비스 포인트 지급           |
| 회수 | 서비스 포인트 회수           |

취소·원복 성격의 `REVERSAL`은 위 업무와 동일한 새 거래로 오해하지 않도록 구분합니다. 통계의 반영 방식은 [통계 기준](statistics.md)을 따릅니다.

금액·대상·사유와 멱등 키를 검증합니다. 같은 키와 같은 내용은 기존 결과를 반환하고, 같은 키에 다른 내용이면 거절합니다. 지갑 잠금과 고정된 잠금 순서로 중복 차감과 경쟁 요청을 방어합니다. 서비스 포인트 일괄 지급·회수는 대상 중 일부만 성공하지 않도록 처리합니다.

## 환불

환불 신청 권한과 처리 권한은 다릅니다. 신청자가 처리 권한도 보유하면 직접 완료 경로를 사용하고, 그렇지 않으면 대기 신청과 유상 예약 잔액을 만듭니다. '총괄 역할이면 즉시 환불'이 아니라 **실제 처리 permission**이 기준입니다.

승인 시 유상 잔액을 차감하고 예약을 해제합니다. 반려 시 예약만 해제하고 완료 거래를 만들지 않습니다. 계좌 등 민감값은 보호하며 증빙 파일 접근을 제한합니다. 공급가·부가세·합계는 서버 계산을 따릅니다.

실제 PG 송금·결제가 서버 내부 완료 Action과 동일한 의미는 아닙니다. 운영 결제 제공자와 대사·송금 실행 범위는 별도 확인이 필요합니다.

## 상담신청 단가

이벤트는 성형·쁘띠·기획전의 기본 단가표를 구분합니다. 대표 카테고리의 상위 분류 기준으로 카테고리값 또는 기본값 사용 여부를 결정합니다. 기획전은 별도 기본표를 가집니다.

범위는 이전 상한 초과부터 현재 상한 이하입니다. 첫 구간은 하한을 따로 편집하지 않고 마지막 구간은 상한 없음입니다. 중간 상한은 이전보다 커야 하며 하한을 파생해 구간 누락·중첩을 막습니다. 표시 단위 만원과 저장 단위 원을 혼동하지 않습니다.

초기 이벤트 기본표는 상한 5·10·20·30·50·80·100·150·250·300·400만원·무제한이며 단가는 10,000~40,000P로 설정됩니다. 정확한 각 값은 [단가 초기값](../../database/seeders/ConsultationPricingSeeder.php)과 Resolver가 관리합니다.

비대면·리얼모델은 각각 하나의 고정 단가이며 초기값은 10,000P입니다. 카테고리별 구간표를 적용하지 않습니다.

## 즉시 적용과 예약

가격 설정은 범위별 현재 설정과 버전으로 관리합니다. 유효 시각 이하의 최신 버전을 조회할 때 선택하므로 예약 시각마다 별도 활성화 배치를 돌리는 구조가 아닙니다.

- 즉시 적용과 미래 시각 예약을 구분합니다.
- 같은 범위에 대기 예약이 있으면 먼저 취소하거나 해당 정책에 맞게 처리해야 새 변경이 가능합니다.
- 갱신 버전을 비교해 다른 관리자의 저장을 덮어쓰지 않습니다.
- 이벤트 신청은 신청 당시 단가 스냅샷, 비대면 답변은 최초 답변 당시 단가를 사용합니다.

## 광고 비용과 권한

광고 비용도 기본 가격·적용 버전을 관리합니다. 현재는 위치별 기본값 편집이며 순번·카테고리별 상세 요금 편집은 연결되지 않습니다. 기존 광고·예약의 가격 스냅샷을 새 기본값으로 소급 변경하지 않습니다.

현황 조회, 거래 내역 조회, 병의원 지갑 관리와 각 지급·회수·환불 처리 권한을 구분합니다. 단가 조회·관리도 별도 권한입니다.
