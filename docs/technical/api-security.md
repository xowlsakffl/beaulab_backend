# API와 보안 계약

## API 주체

기본 경로는 `/api/v1/{staff|hospital|user|beauty}`입니다. 같은 URL 하위 기능이어도 공개 조회·웹 전용·사용자 토큰 허용을 구분합니다.

직원·병의원·뷰티 관리 API는 웹 세션 흐름을 사용합니다. 사용자 API는 허용 경로에서 웹 세션 또는 `actor:user` 앱 토큰을 받을 수 있습니다. 앱 토큰 계약이 있다는 이유로 네이티브 앱이 구현되어 있는 것은 아닙니다.

사용자 앱 로그인은 Bearer 토큰을 반환할 수 있습니다. 현재 `ActorAuthentication`은 토큰 발급에 만료 시각을 지정하지 않고 `config/sanctum.php`의 expiration도 null이며 사용자 refresh endpoint는 없습니다. 웹 세션의 최대 30일을 앱 토큰 수명으로 설명하면 안 됩니다. 네이티브 클라이언트를 공개하기 전 토큰 만료·기기별 회수·재로그인 정책을 확정해야 합니다.

## 웹 인증

브라우저는 동일 출처 Next rewrite를 통해 쿠키로 요청하고 `X-Beaulab-Client: web`과 주체별 CSRF를 사용합니다. 서버는 요청 Origin, 세션 주체, CSRF, 계정 상태를 검증합니다.

| 주체             | 기본 미사용 제한 | 기본 절대 제한 |
| ---------------- | ---------------- | -------------- |
| 직원·병의원·뷰티 | 120분            | 1,440분        |
| 일반회원         | 10,080분         | 43,200분       |

실제 값은 [web_auth 설정](../../config/web_auth.php)과 환경변수를 따릅니다. 사용자 활동 보고와 단순 백그라운드 조회를 구분합니다.

세션·CSRF 초기화, 로그인·로그아웃 등 필요한 경우에 쿠키를 갱신하고 일반 API 응답에서 불필요하게 세션 쿠키를 반복 발급하지 않습니다. 여러 요청의 오래된 응답이 새 로그인 쿠키를 덮어쓰는 경쟁을 피하기 위한 경계입니다.

프론트는 프로필·CSRF를 메모리에 두고 새로고침 때 서버에서 복구합니다. 비밀번호·브라우저 세션 토큰을 localStorage에 저장하지 않습니다. 로그인 실패와 세션 확인 서버 오류를 같은 401로 처리하지 않습니다.

## 인가

인증은 누구인지, 인가는 무엇을 할 수 있는지입니다. 직원 개인 permission, 병의원 소유권, 회원 리소스 소유권·채팅 참여자 조건을 각각 검사합니다.

초기화된 직원에게 역할 권한을 자동 합산하지 않습니다. [직원 권한](../business/staff-permissions.md)이 업무 기준입니다. 클라이언트의 권한 배열과 숨겨진 버튼은 보안 경계가 아닙니다.

인증 링크·직접 파일·채널 구독도 별도 접근 검증이 필요합니다. 본문 API만 보호하고 다운로드나 실시간 경로를 열어 두지 않습니다.

## 응답

성공 응답은 `success, data, meta, traceId`, 실패는 `success: false, error: {code, message, details?}, traceId` 형식입니다. 페이지네이션 정보는 각 목록 DTO·meta를 따릅니다. 파일·CSV 응답은 JSON 봉투와 다릅니다.

| 상태             | 의미 / 클라이언트 처리                              |
| ---------------- | --------------------------------------------------- |
| 401              | 인증 복구 실패·만료. 보호 화면 로그인 이동          |
| 403              | 권한·소유권 거부. 페이지 접근과 개별 액션 오류 구분 |
| 404              | 대상 없음 또는 숨겨야 하는 대상                     |
| 419              | CSRF 또는 공개 인증 링크 관련 오류 코드 확인        |
| 422 등 검증 오류 | 서버 필드 오류를 입력 영역에 표시                   |
| 429              | 요청 제한. 자동 변경 요청 재전송 금지               |

실제 HTTP 상태는 ErrorCode·예외 변환을 확인합니다. 문구 문자열만 비교해 모든 오류를 한 가지 상태로 분류하지 않습니다. traceId는 로그 연계용이지 사용자에게 민감한 원문을 노출하는 수단이 아닙니다.

## 민감 정보와 파일

비밀번호·초대·재설정·인증 코드·쿠키·전체 개인정보를 로그에 남기지 않습니다. 설정·계정·토큰 원문을 문서·테스트 산출물에 넣지 않습니다.

미디어는 공개 홍보 이미지와 비공개 증빙 컬렉션을 구분합니다. API가 반환하는 미디어 URL·서명 경로를 사용하고 저장소 경로를 프론트에서 추측하지 않습니다. 상대 서명 링크, 만료 시각, 사용자 접근 정책을 보존합니다.

현재 비공개 미디어 원본은 5분 서명 URL을 발급하는 방식입니다. 유효한 링크를 가진 사람의 접근과 매번 로그인 권한을 재검사하는 방식은 같지 않습니다. URL을 로그·분석 도구·공개 캐시에 남기지 않고, 권한 회수 즉시 이미 발급한 링크도 폐기되는 것으로 설명하지 않습니다. 비대면 사진 등은 확대·만료 시 인증된 상세 조회로 새 URL을 받아야 합니다.

## 자동 API 문서와 내부 도구

Scramble은 `api/v1` 라우트에서 명세를 생성합니다. Request·DTO와 실제 오류·다운로드 계약을 함께 확인해야 하며 자동 명세가 모든 업무 전환을 설명하는 것은 아닙니다.

Scramble은 web·IP 제한·`tool_staff` 인증·`viewTool` Gate로 보호됩니다. Horizon·Telescope도 내부 도구 접근 정책을 따릅니다. 운영에서 공개 도구 URL을 열거나 일반 직원 쿠키가 도구 권한을 대신한다고 가정하지 않습니다.

- [미들웨어 구현](../../app/Common/Http/Middleware), [내부 도구](../../app/Providers/InternalToolServiceProvider.php)
- [API 문서 설정](../../config/scramble.php), [미디어 설정](../../config/media.php)
