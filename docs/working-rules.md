# 작업 규칙

## 변경의 범위

실제 업무 계약을 먼저 확인하고 필요한 부분만 변경합니다. 계층 분리·네이밍 통일·공통화 자체를 작업 목표로 삼지 않습니다. 같은 UI여도 상태 전환·검증·소유권·과금 이유가 다르면 도메인에 둡니다.

- 시작 전 현재 브랜치, 변경 파일, 관련 AGENTS와 기준서를 확인합니다.
- 기존 미커밋 변경을 초기화하거나 사용자 작업을 덮어쓰지 않습니다.
- 사용자 요청 없이 커밋·푸시·배포하지 않습니다. 브랜치 기준은 현재 요청을 따르며, 별도 지정이 없으면 master에서 작업 브랜치를 분기하고 PR로 검토합니다.
- 비밀값·실제 개인정보·DB 덤프·인증 쿠키·임시 산출물을 저장소에 넣지 않습니다.
- 사용자 문구와 샘플은 한국어로 작성합니다. 기술 식별자·상태 코드·URL은 번역하지 않습니다.

## master 동기화

회사 원격 `origin`과 개인 원격 `xowlsakffl`은 각 저장소에서 동일한 `master` 커밋을 유지합니다. 개인용 코드·README·문서 분기는 따로 운영하지 않습니다.

| 저장소 | 회사 원격 (`origin`)           | 개인 원격 (`xowlsakffl`)      |
| ------ | ------------------------------ | ----------------------------- |
| 백엔드 | `beaulab/beaulab_new_dev`      | `xowlsakffl/beaulab_backend`  |
| 프론트 | `beaulab/beaulab_new_frontend` | `xowlsakffl/beaulab_frontend` |

사용자가 커밋·푸시를 요청하면 검증한 `master`를 `origin`에 먼저 푸시하고, 성공한 같은 커밋을 `xowlsakffl`에도 푸시합니다. 마지막에는 두 원격의 `refs/heads/master`와 로컬 `master`의 SHA가 일치하는지 확인합니다. 일부 원격만 성공하면 그 상태를 보고하고 완료로 처리하지 않습니다.

`git push --mirror`로 다른 브랜치·태그·보관 참조까지 전송하지 않습니다. 원격 이력이 갈라지면 원인을 확인하고, 별도 승인 없이 강제 푸시하지 않습니다. 로컬 Git 설정에만 의존하지 않고 두 원격을 명시해서 푸시합니다.

## 승인과 실행 경계

DB 초기화·마이그레이션·시딩·권한 복사·업무 데이터 수정은 연결 호스트, DB 이름, 변경 범위를 설명하고 승인받습니다. 과거의 로컬 승인으로 다른 환경이나 다른 범위까지 승인된 것으로 보지 않습니다.

메일·SMS·푸시·결제, 큐 소비·재시도, 스케줄러·실시간 서버 시작, 배포·서비스 재시작도 실제 부작용을 확인합니다. 읽기 전용 점검과 실행을 구분하고 업무 DB에서 테스트하지 않습니다.

## 검증

- 백엔드: 변경 PHP 구문, Pint 검사, 관련 PHPUnit을 우선합니다. DB 테스트는 [격리된 테스트 환경](operations/local-development.md)에서만 실행합니다.
- 프론트: 린트·타입 검사·빌드·브라우저 확인을 사용합니다. 현재 정책상 테스트 파일·러너·의존성을 임의로 추가하지 않습니다.
- 성능은 측정 조건·데이터 크기·쿼리 수·시간을 함께 보고합니다. 정적 코드상 위험과 실제 병목을 구분합니다.
- 문서만 바꾸면 링크·코드 참조·누락·기존 문서의 소비 경로를 확인합니다. DB나 전체 빌드는 필요하지 않습니다.
- 실행하지 않은 검증, 확인하지 못한 역할·예외 경로를 명시합니다.

## DB 스키마

현재 저장소의 개발 단계 규칙은 기존 테이블 변경을 원래 생성 마이그레이션에 반영하고, 새 테이블은 생성 마이그레이션으로 추가하는 것입니다. 이 규칙은 **이미 적용된 DB가 자동으로 갱신된다는 뜻이 아닙니다**.

적용된 환경에서는 기존 마이그레이션 수정만으로 부족합니다. 스키마 차이, 보존할 데이터, 별도 전환 절차·백업·복구를 확인하고 승인받습니다. 운영 환경에 그대로 `migrate:fresh`를 적용하거나 변경 이력을 임의 삭제하지 않습니다.

## 문서와 코드의 동기화

| 변경 대상                         | 함께 확인할 문서      |
| --------------------------------- | --------------------- |
| 업무 상태·연관 데이터·권한·부작용 | 해당 `docs/business/` |
| 메뉴·API 연결·구현 범위           | `feature-map.md`      |
| 인증·오류·외부 호출·큐            | `technical/`          |
| 환경 변수·시드·명령·배포 절차     | `operations/`         |
| 화면 배치·공통 UI·클라이언트 캐시 | 프론트 `docs/`        |
| 작업 안전장치·검증 정책           | 각 저장소 `AGENTS.md` |

문서는 목적, 현재 규칙, 실패 조건, 관련 코드를 설명합니다. 완료 보고·작업 날짜별 나열·개인별 작업 지시는 넣지 않습니다. 미구현·정책 미정·운영 미검증을 구현된 기능과 섞지 않습니다.

## 링크와 책임

같은 저장소는 상대 링크, 다른 저장소는 GitHub 저장소 링크를 씁니다. 로컬 사용자명·WSL 경로를 문서 링크에 고정하지 않습니다. 자동 API 명세나 마이그레이션으로 확인할 수 있는 전체 필드·DDL을 별도 수동 파일에 복제하지 않습니다.
